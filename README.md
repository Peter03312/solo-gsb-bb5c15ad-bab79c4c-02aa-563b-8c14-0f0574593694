# 脱敏文稿发布工作台

供小团队在**本地/内网**完成敏感文稿脱敏评审与发布的网页工作台。
Python（FastAPI）+ SQLite + 原生 HTML/JS，无任何第三方登录或外部服务依赖。

## 工作流程

1. **作者**粘贴正文创建文稿，得到第 1 个**不可变版本**。修改正文必须另建版本；
   旧版本的提议、裁决、确认全部封存，**不会沿用**到新版本。
2. **审阅人**在当前版本的正文上拖选文字（索引按 Unicode 码位，emoji 等字符定位准确），
   填写理由后提交遮盖提议，并可在裁决前**撤回自己的未决提议**（已裁决不可撤）。
3. **另一名审阅人**逐条**接受 / 驳回**；任何人不能裁决自己的提议。
4. 范围重叠时，预览与导出只遮盖**接受范围的并集**，每条提议仍保留独立裁决。
5. 全部提议裁决完毕后，由**两名不同且非作者**的审阅人确认同一份最终预览
   （以预览内容的 SHA-256 指纹为准）。任何裁决/撤回/新提议都会**立即使全部确认失效**。
6. 作者在满足条件时才能**发布**；发布所需的全部校验与状态变更在一个
   `BEGIN IMMEDIATE` 事务内原子完成。并发的过期操作（`state_rev` 乐观锁不匹配）
   一律返回 `409`，前端提示刷新。
7. **导出永远只包含遮盖后的文本**（`█` 替换被遮盖区段），不包含原文；未完成裁决时不可导出最终稿。

## 快速启动（Docker，一次启动并建好数据库）

```bash
docker compose up -d --build
```

- 启动时若数据库为空会自动建表（SQLite 文件位于卷 `redaction-data`，容器内 `/data/redact.db`），
  并按下表创建本地账号。
- 访问地址：**http://localhost:8000**（端口可在 `docker-compose.yml` 修改）。
- 停止：`docker compose down`（数据保留在命名卷中；`docker compose down -v` 同时删除数据）。

## 本地直接运行（不用 Docker）

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 数据库目录需要可写；下面会在首次启动时自动建库建表
export DB_PATH="./data/redact.db"
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

然后打开 http://localhost:8000 。

## 默认账号（首次启动自动初始化）

| 角色 | 用户名 | 密码 | 权限 |
|---|---|---|---|
| 作者 | `author` | `author123` | 创建文稿/版本、发布 |
| 审阅人 | `reviewer1` | `review123` | 提议、裁决他人提议、确认最终预览 |
| 审阅人 | `reviewer2` | `review123` | 同上 |

> 审阅人需要至少两个账号，才能满足“另一名审阅人裁决”和“两名审阅人确认”的要求。

## 配置项（环境变量）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8000` | 服务监听端口 |
| `DB_PATH` | `/data/redact.db` | SQLite 数据库文件路径；所在目录不存在会自动创建 |
| `SESSION_SECRET` | `dev-secret-change-me` | 会话 Cookie 的 HMAC 签名密钥，**生产请用 `openssl rand -hex 32` 改写** |
| `SESSION_TTL_DAYS` | `7` | 登录会话有效期（天） |
| `SEED_AUTHOR_USER` / `SEED_AUTHOR_PASS` | `author` / `author123` | 初始作者账号，仅在库中无用户时创建 |
| `SEED_REVIEWER1_USER` / `SEED_REVIEWER1_PASS` | `reviewer1` / `review123` | 初始审阅人账号 1 |
| `SEED_REVIEWER2_USER` / `SEED_REVIEWER2_PASS` | `reviewer2` / `review123` | 初始审阅人账号 2 |

改端口示例：把宿主机端口改为 9000 只需在 `docker-compose.yml` 把映射改为 `"9000:8000"`
（容器内 `PORT` 可保持 8000），随后访问 http://localhost:9000 。

## 网页功能页

登录后顶部导航包含：

- **待办**：审阅人看到“待我裁决 / 我的未决提议 / 待我确认的预览”；作者看到“可发布/等待确认的版本”。
- **文稿与版本**：全部文稿列表及发布状态；点入可查看不可变版本历史、另建新版本。
- **新建文稿**（作者）：粘贴正文创建 v1。
- **发布记录**：已发布版本一览，可直接下载脱敏文本。
- 版本工作台分三栏：**原文 + 选区操作**、**提议清单（接受/驳回/撤回）**、
  **遮盖并集预览 + 确认/发布区**。

## 规则与错误提示

- 非法选区（空选区、越界、作用于历史版本）、越权操作（作者试图裁决、裁决自己的提议、
  非作者发布、确认人数不足等）、以及并发过期提交，后端分别返回
  `400 / 403 / 409` 并带有明确中文错误，前端以提示条展示并在 409 时刷新数据。
- 版本正文字段在应用层没有任何修改路径；新版本是全新的一行记录。
- 导出接口（`GET /api/versions/{id}/export`）只输出掩码文本，
  发布前要求全部提议已裁决，发布后任何人（登录后）可下载已发布版本的脱敏稿。

## 技术说明

- 后端 `FastAPI` + 标准库 `sqlite3`（WAL 模式，外键开启）；
  写操作使用 `BEGIN IMMEDIATE`，读取自动提交。
- 选区索引统一为 **Unicode 码位**：Python 的字符串下标天然是码位；
  前端用 `Array.from(str)`（基于字符串迭代器）完成 UTF-16 偏移到码位的换算。
- 会话为 HMAC-SHA256 签名的自包含 HttpOnly Cookie；口令使用 PBKDF2 加盐哈希。
- 健康检查：`GET /healthz`。
